# 마이페이지 제품·개발 가이드

> 상태: implemented-with-mock-gaps
> 최종 확인: 2026-08-26
> 근거: Figma `987:7124`, `824:6502`, `src/pages/my-page`, `src/components/AppShell/ProfileMenu.tsx`

마이페이지는 Figma의 정보 구조를 공통 `AppShell` 안에 구현한다. 실제 API와 샘플 데이터의 정확한 경계는 [`mypage-data-sources.md`](./mypage-data-sources.md)를 기준으로 판단한다.

## 화면과 경로

| 경로            | 화면            | 진입                                     |
| --------------- | --------------- | ---------------------------------------- |
| `/my-page`      | 마이페이지 조회 | AppShell 우측 프로필 메뉴의 `마이페이지` |
| `/my-page/edit` | 내 정보 수정    | 프로필 카드의 수정 버튼                  |

마이페이지는 기본 탭 중 하나를 선택하지 않고 `currentPageLabel`로 현재 위치를 표시한다. 정식 라우터를 추가하지 않으며 `src/app.tsx`와 `navigate()`의 기존 경량 라우팅을 사용한다.

## Figma 기준 정보 구조

1850px 이상에서는 Figma 좌표와 같은 `689 : 696 : 356` 비율과 `16~17px` 열 간격으로 3열을 배치한다. 1500~1849px에서는 각 주요 카드에 필요한 660px를 보장하는 2열, 그보다 작은 화면에서는 1열로 재배치한다. 카드 내부의 Figma 고정 좌표가 잘리지 않도록 콘텐츠 최소 폭은 680px로 유지하며, 더 작은 화면에서는 페이지 콘텐츠 영역을 가로 스크롤할 수 있다.

1. 왼쪽: 프로필, 매수·매도 일지 현황
2. 가운데 위: 가상계좌
3. 가운데 아래: 관심종목
4. 오른쪽: 이용 현황, 주문 내역

Figma 레이어 `987:7243`의 이름은 `내 계좌`지만 제품 의미는 사용자가 확인한 `가상계좌`다. 왼쪽 영역도 단순 매도·매수 수치가 아니라 `매수·매도 일지 현황`이다.

## 컴포넌트 경계

- `MyPage`: API 요청, API 실패 시 샘플 대체, 관심종목 삭제 상태, 3열 조립
- `ProfileCard`: 세션 사용자 표시와 수정 화면 진입
- `DiaryActivityCard`: 3×4 월 히트맵, 조회 연도, 매수/매도 필터, GitHub 브랜치 그래프 형태의 일지 목록
- `VirtualAccountCard`: 포트폴리오별 가상계좌 요약
- `FavoriteStocksCard`: 관심종목 목록과 해제
- `UsageSummaryCard`, `RecentOrdersCard`: 계약이 없는 정보의 명시적 샘플 표시
- `MyPageEditPage`: 브라우저 세션 사용자 정보 수정 시연과 입력 검증
- `ProfileMenu`: 모든 AppShell 화면에서 공통으로 쓰는 마이페이지/로그아웃 메뉴

페이지는 공통 헤더, 검색창, 내비게이션, 외부 패널을 복제하지 않는다. 공용 표면은 `BaseCard`, 동작 버튼은 공용 `Button`, 색은 기존 토큰을 우선 사용한다.

## 주요 동작

- 선택한 연도의 일지를 페이지 끝까지 조회하고, Figma의 3×4 월 히트맵에서 월을 고른 뒤 전체/매수/매도로 필터링한다. 상세 일지는 매수·매도 레인이 분기되는 GitHub 브랜치 그래프 형태이며 최신순/금액순 정렬을 지원한다.
- 관심종목 해제는 API 데이터일 때 낙관적으로 반영하며 실패하면 복원한다.
- 일지·관심종목·포트폴리오 API가 실패하면 해당 영역만 샘플 데이터로 대체하고 화면 상단 경고로 알린다.
- 프로필 수정은 필수값과 새 비밀번호 일치 여부를 검사한다.
- 프로필 수정 API가 없으므로 이름·닉네임·이메일만 로컬 세션 사용자에 저장한다. 비밀번호, API Key/Secret, 이미지와 Google 연결 상태는 저장하지 않는다.
- 로그아웃은 사용자와 access token 캐시를 지운다. 서버 로그아웃 API가 없어 refresh cookie 폐기는 보장하지 않는다.

## 보안과 접근성

- 비밀번호와 API Secret 입력은 마스킹하고 localStorage, URL, 로그에 기록하지 않는다.
- 프로필 메뉴는 MUI Menu의 바깥 클릭, Escape, 포커스 복귀 동작을 사용한다.
- 아이콘 버튼은 동작을 설명하는 `aria-label`을 가진다.
- 로딩, 빈 목록, API 실패, 삭제 실패를 사용자에게 구분해 표시한다.

## 후속 백엔드 계약

다음 기능은 Swagger 계약이 추가된 뒤 샘플을 제거한다.

- 사용자 프로필 조회/수정, 이미지 업로드, 비밀번호 변경
- Google 계정 연결/해제, 증권 API credential 저장
- 가상계좌 잔액·보유자산
- 관심종목 현재가·산업·로고
- 이용 통계
- 타입이 명확한 최근 주문 목록
- 서버 로그아웃
