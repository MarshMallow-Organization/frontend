# 마이페이지 개발 가이드

> 이 문서는 마이페이지를 구현하는 사람과 AI 에이전트가 공통 레이아웃을 중복 개발하지 않도록 작업 경계를 정의한다.  
> 현재 단계에서는 설계 기준만 기록하며, 마이페이지 UI 구현은 시작하지 않는다.

## 1. 가장 먼저 확인할 파일

- 공통 최상위 레이아웃: `src/components/AppShell/AppShell.tsx`
- AppShell 사용법: `src/components/AppShell/README.md`
- 올바른 적용 예시: `src/pages/trade-journal/TradeJournalPage.tsx`
- 공통 디자인 토큰: `src/theme/tokens.ts`
- 공통 컴포넌트 목록: `src/components/README.md`
- 임시 라우팅 진입점: `src/app.tsx`

마이페이지 작업 전 위 파일들의 최신 내용을 다시 읽는다. 이 문서보다 실제 코드가 변경된 경우 실제 코드를 기준으로 판단하되, 공통 영역을 페이지 안에 복제하지 않는 원칙은 유지한다.

## 2. 공통 영역과 마이페이지 영역의 경계

로그인 이후 화면의 공통 최상위 레이아웃은 `AppShell`이 담당한다.

### AppShell이 이미 담당하는 공통 영역

- 전체 페이지 배경과 최소 화면 높이
- 상단 Marsh Mallow 워드마크
- 홈 아이콘
- 상단 주요 탭 영역
  - 관심종목
  - 인기종목
  - 내 계좌
  - 매매일지
- 상단 종목 검색창
- 우측 사용자 아바타
- 본문 바깥 여백
- 둥근 모서리, 테두리, 배경 그라데이션을 포함한 공통 콘텐츠 패널
- 공통 콘텐츠 패널의 최대 너비와 최소 높이

위 항목은 마이페이지 컴포넌트에서 다시 만들거나 스타일을 복사하지 않는다.

### 마이페이지가 담당할 영역

마이페이지는 `AppShell`의 `children`으로 들어가는 패널 내부 콘텐츠만 담당한다.

예상되는 페이지 전용 영역은 다음과 같다. 실제 디자인이 확정되면 항목을 조정할 수 있다.

- 마이페이지 제목과 페이지 내부 설명
- 사용자 프로필 정보 표시 및 수정 UI
- 계정 또는 개인 설정 UI
- 마이페이지 안에서만 사용하는 카드, 목록, 폼, 다이얼로그
- 페이지 전용 상태와 이벤트 처리
- 마이페이지 전용 API 연동과 타입
- 패널 내부의 반응형 배치

## 3. 구현 시 기본 구조

마이페이지의 기본 진입 컴포넌트는 아래 형태를 따른다.

```tsx
import { AppShell } from '../../components/AppShell';

export default function MyPage() {
  return (
    <AppShell activeNav="account">
      {/* 마이페이지 전용 콘텐츠만 작성 */}
    </AppShell>
  );
}
```

마이페이지 전용 파일은 다음 구조를 기본안으로 사용한다. 디자인과 기능 규모가 작다면 불필요한 하위 파일을 미리 만들지 않는다.

```text
src/pages/my-page/
├── MyPage.tsx
├── components/       # 마이페이지에서만 사용하는 UI
├── types.ts          # 마이페이지 전용 타입이 있을 때만 생성
└── mock-data.ts      # 실제 API 전 임시 데이터가 필요할 때만 생성
```

여러 페이지에서 재사용되는 것이 확인된 컴포넌트만 `src/components`로 올린다. 처음부터 재사용을 예상해 전용 컴포넌트를 공용 폴더에 두지 않는다.

## 4. `activeNav` 선택 기준

현재 `AppShellNav` 타입은 다음 값만 지원한다.

```ts
'watchlist' | 'popular' | 'account' | 'journal';
```

현재 마이페이지 전용 탭은 없으므로 우선 `activeNav="account"`를 사용한다. 마이페이지 디자인이나 기획에서 별도 탭이 확정되면 페이지 내부에서 우회 구현하지 말고, 먼저 `AppShellNav`와 공통 내비게이션 정책을 수정해야 한다.

우측 아바타 클릭으로 마이페이지에 진입하는 동작은 아직 `AppShell`에 구현되어 있지 않다. 마이페이지 개발자가 아바타를 새로 만들지 말고, 마이페이지 경로가 확정된 뒤 공통 `AppShell`의 경량 내비게이션에 기능을 추가한다.

## 5. 반드시 지킬 구현 원칙

### 공통 UI를 복제하지 않는다

마이페이지 안에서 별도의 `<header>`, 로고, 홈 버튼, 상단 검색창, 사용자 아바타 또는 바깥쪽 배경 패널을 만들지 않는다. AppShell과 비슷한 CSS를 페이지 파일에 복사하는 것도 금지한다.

### 공통 토큰과 컴포넌트를 먼저 확인한다

색상, 글꼴, 테두리 색상 등을 새 값으로 선언하기 전에 `src/theme/tokens.ts`를 확인한다. 버튼, 카드, 입력 필드, 선택 UI가 필요하면 `src/components`의 기존 컴포넌트를 우선 검토한다.

기존 공용 컴포넌트가 디자인 요구사항을 충족하지 못할 경우:

1. 기존 API로 조합할 수 있는지 확인한다.
2. 다른 사용처를 깨뜨리지 않는 선택적 prop 또는 variant 추가를 검토한다.
3. 마이페이지에만 필요한 형태라면 페이지 전용 컴포넌트로 둔다.

### 페이지 전용 로직을 AppShell에 넣지 않는다

프로필 조회, 닉네임 수정, 설정 저장, 마이페이지 다이얼로그 상태 등은 마이페이지 영역에서 관리한다. `AppShell`에는 로그인 이후 모든 페이지에 공통인 동작만 추가한다.

### 임시 라우팅을 실제 라우터로 오해하지 않는다

현재 `src/app.tsx`는 URL pathname과 hash를 검사하고 `src/lib/navigation.ts`의 History API 이동을 사용하는 경량 라우팅 구조다. 마이페이지 진입 경로를 추가할 때 기존 분기를 무작정 교체하거나 새로운 라우팅 라이브러리를 독단적으로 도입하지 않는다. 프로젝트의 라우팅 정책을 확인한 뒤 최소 변경으로 연결한다.

## 6. 현재 코드에서 주의할 점

- `TradeJournalPage`는 `AppShell`을 사용하는 기준 예시다.
- `NewsPage`는 자체 헤더와 외부 패널을 포함하고 있어 현재 공통 AppShell 기준을 따르지 않는다. 마이페이지 구현 시 `NewsPage`의 최상위 구조를 복사하지 않는다.
- AppShell의 인기종목 탭은 `/news/popular`, 매매일지 탭은 `/journal`에 연결되어 있다. 아직 실제 페이지가 없는 관심종목과 내 계좌 탭은 비활성 상태다.
- AppShell의 상단 검색창과 메뉴 버튼 동작은 아직 미구현이다.
- AppShell의 아바타는 현재 고정 문자 `U`를 표시한다.
- 사용자 정보 모델, 인증 사용자 조회 방식, 프로필 수정 API는 아직 이 문서에서 확정하지 않는다.
- API 명세가 없는 값을 추측해 영구 타입이나 요청 코드를 만들지 않는다. 목업을 사용한다면 목업임을 파일과 코드에서 명확히 표시한다.

## 7. 디자인 전달 후 개발 순서

1. 전달된 디자인에서 AppShell 바깥/상단 공통 영역을 제외한다.
2. 패널 내부에 필요한 섹션과 상태를 목록화한다.
3. `src/components`에서 재사용 가능한 공용 컴포넌트를 확인한다.
4. 마이페이지 전용 컴포넌트 경계를 정한다.
5. API 명세와 인증 사용자 데이터 형태를 확인한다.
6. `MyPage.tsx`를 AppShell의 자식으로 구현한다.
7. 프로젝트 라우팅 정책에 맞춰 진입 경로를 연결한다.
8. 타입 검사, lint, 빌드와 주요 화면 크기를 검증한다.

## 8. 작업 완료 체크리스트

- [ ] `MyPage`가 `AppShell`을 사용한다.
- [ ] 페이지 파일에 공통 헤더와 외부 패널을 중복 구현하지 않았다.
- [ ] 마이페이지 전용 콘텐츠만 AppShell의 `children`에 들어간다.
- [ ] 기존 디자인 토큰과 공용 컴포넌트를 먼저 재사용했다.
- [ ] 마이페이지 전용 상태와 API 로직이 AppShell에 섞이지 않았다.
- [ ] 임시 데이터와 실제 API 데이터를 명확히 구분했다.
- [ ] 라우팅 변경이 기존 로그인, 뉴스, 매매일지 진입을 깨뜨리지 않는다.
- [ ] TypeScript 검사와 프로덕션 빌드가 통과한다.
- [ ] 작은 화면에서 패널 내부 콘텐츠가 잘리거나 겹치지 않는다.

## 9. AI 에이전트용 작업 지시 요약

마이페이지 작업 요청을 받은 AI는 다음 규칙을 우선 적용한다.

1. 구현 전에 이 문서와 `AppShell` 코드를 읽는다.
2. 사용자가 명시적으로 개발 시작을 요청하기 전에는 UI 코드를 작성하지 않는다.
3. 최상위 공통 UI는 `AppShell`을 재사용하고 복제하지 않는다.
4. 마이페이지에서는 공통 패널 안쪽 콘텐츠만 구현한다.
5. 불명확한 디자인, API 또는 라우팅 정책을 임의로 확정하지 않는다.
6. AppShell 변경이 필요하면 페이지 작업과 구분해 변경 이유와 다른 페이지 영향도를 먼저 확인한다.
7. 뉴스 페이지의 자체 헤더 구조를 마이페이지의 기준으로 사용하지 않는다.
