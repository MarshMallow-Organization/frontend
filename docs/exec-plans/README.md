# Execution Plans

> 상태: active-process  
> 최종 확인: 2026-08-19

여러 영역을 건드리거나 중간 결정이 남는 작업은 실행 계획을 저장소에 남긴다. 단순한 한 파일 수정에는 계획 문서를 만들 필요가 없다.

## 언제 작성하는가

- 공용 API, AppShell, 라우팅처럼 영향 범위가 넓은 변경
- 여러 PR 또는 여러 작업 세션에 걸치는 변경
- 데이터 마이그레이션이나 호환성 전략이 필요한 변경
- 새 도구·의존성·테스트 기반 도입
- 실패 시 복구 절차가 필요한 변경

## 파일 위치

```text
docs/exec-plans/
├── active/       # 진행 중인 계획; 필요할 때 생성
├── completed/    # 완료 후 이동; 필요할 때 생성
└── tech-debt.md  # 장기 부채 목록
```

## 계획에 포함할 내용

1. 문제와 사용자 관점의 완료 조건
2. 범위와 명시적 비범위
3. 확인한 코드·문서·계약
4. 단계별 구현과 각 단계의 검증
5. 결정 기록과 대안
6. 롤백 또는 호환성 전략
7. 진행 상태, 남은 위험, 최종 결과

계획은 현재 상태를 반영하는 살아 있는 문서다. 끝난 체크리스트만 남기지 말고 예상과 달랐던 점, 검증 증거, 다음 사람이 이어갈 수 있는 정보를 갱신한다.
