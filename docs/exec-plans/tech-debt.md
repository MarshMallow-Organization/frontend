# Frontend Technical Debt

> 상태: active-register  
> 최종 확인: 2026-08-19

| 우선순위 | 항목                                                           | 현재 영향                                                            | 완료 조건                                   |
| -------- | -------------------------------------------------------------- | -------------------------------------------------------------------- | ------------------------------------------- |
| P0       | 비수정 `format:check`, `lint:check`, `typecheck`, `check` 없음 | 에이전트가 명령을 기억해야 하고 기존 파일을 뜻밖에 수정할 수 있음    | `package.json`과 CI가 같은 비수정 명령 사용 |
| P0       | API 래퍼가 백엔드 공통 응답 계약과 불일치                      | `{ data }`와 `code/message/traceId` 처리가 호출부마다 달라질 수 있음 | 래퍼 구현과 계약 테스트 통과                |
| P0       | `.env.example` 없음                                            | 지원 환경변수와 목업 기본값을 발견하기 어려움                        | 안전한 예제와 설명 추가                     |
| P0       | CI가 ESLint만 실행                                             | 타입·빌드·문서 오류가 merge 전 누락될 수 있음                        | `yarn check`, `yarn build`, 문서 검사 실행  |
| P1       | 테스트 프레임워크와 단위 테스트 없음                           | 상태·변환·오류 처리 회귀를 자동으로 잡지 못함                        | 핵심 로직 테스트와 CI 연동                  |
| P1       | 경량 라우팅이 문자열 분기에 의존                               | 화면 증가 시 alias와 활성 탭 동기화가 어려움                         | 요구가 생기면 실행 계획으로 라우터 도입     |
| P2       | 브라우저 E2E·시각 회귀 없음                                    | AppShell·반응형 회귀가 수동 확인에 의존                              | 핵심 흐름과 기준 화면 자동화                |
| P2       | 문서 링크·노후화 자동 검사 없음                                | AI가 오래된 지침을 읽을 수 있음                                      | 로컬 링크와 최종 확인일 검사                |

새 부채를 추가할 때는 막연한 개선 아이디어가 아니라 현재 영향과 확인 가능한 완료 조건을 적는다. 해결 PR에서는 해당 행을 삭제하거나 완료 기록으로 옮기고 관련 로드맵도 갱신한다.
